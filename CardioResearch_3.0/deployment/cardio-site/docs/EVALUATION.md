# Диагностика CardioResearch 2.5

Добавлены описательные метрики сохранённых прогнозов и новый ретроспективный опыт переноса модели UCI. Обучение, калибратор, выбор модели и рабочий порог не менялись. Улучшение оценки исследования не означает увеличение качества самой модели.

## Выборки и результаты

| Оценка | n | ROC-AUC | AP | Balanced accuracy |
| --- | ---: | ---: | ---: | ---: |
| BRFSS, фиксированный отложенный тест | 85 748 | 0.83887 | 0.32087 | 0.70146 |
| Cleveland, средние OOF-прогнозы Random Forest | 303 | 0.90906 | 0.90316 | 0.82556 |
| Hungary, фиксированный артефакт Random Forest | 294 | 0.90340 | 0.84448 | 0.80655 |
| Switzerland, тот же артефакт | 123 | 0.74565 | 0.97319 | 0.68913 |
| VA, тот же артефакт | 200 | 0.73325 | 0.87766 | 0.59337 |

OOF-метрики Cleveland отличаются от среднего по шести внешним фолдам. Последнее остаётся в «Сравнении моделей» и сопровождается SD. Результаты разных выборок не объединяются в общий рейтинг. В частности, Switzerland содержит 115 положительных наблюдений из 123; AP 0.973 нельзя называть точностью 97% или улучшением модели.

## Новые показатели

`data/evaluation.json` содержит 19 показателей, матрицы, интервалы Wilson 95% для precision/recall/specificity/NPV, десять равных интервалов калибровки и двадцать интервалов распределения вероятностей. Пустые интервалы и неопределённые отношения сохраняются как `null`, а не нули. Формулы и параметры сохранены в `methods`.

- Balanced accuracy усредняет чувствительность и специфичность; MCC учитывает все четыре клетки матрицы.
- NPV — доля истинно отрицательных среди отрицательных прогнозов; FPR/FNR используют фактический класс в знаменателе.
- AP сопоставляется с долей положительного класса. Постоянный прогноз наиболее частого класса используется только как объяснение ограничений accuracy.
- Brier skill сравнивает Brier модели с описательной константой, равной доле положительных в той же выборке. Это не обученная на train базовая модель.
- ECE зависит от десяти заданных интервалов; малый ECE не доказывает индивидуальную или клиническую калибровку.
- Wilson-интервалы условные и описательные. Они не учитывают обучение/выбор модели, зависимость OOF-прогнозов, веса, страты и кластеры обследования BRFSS. Интервалы не являются одновременными.

BRFSS validation/test показаны для проверки согласованности. Подбор порога остаётся только на сохранённой validation-кривой. По тестовым данным ничего не оптимизируется.

## Перенос на другие центры

`data/transfer.json` получен из исходного `uci_centers_audit.csv` и того же экспортированного артефакта UCI. Cleveland использован только как обучающий центр; метрики на обучающих строках не публикуются. Три других центра ранее просматривались при аудите пропусков, поэтому опыт не называется предварительно зарегистрированным независимым исследованием.

Во всех центрах применяется неизменённое преобразование Cleveland и порог 0.5. Учитываются все 617 записей, без адаптации к центру. Пропуски заполняются обученным преобразованием. Числовые нули сохраняются: в Switzerland холестерин записан нулём во всех 123 строках. Такие значения и выходы за диапазон интерактивной формы отдельно отмечаются. Вызван низкоуровневый прогноз, чтобы ограничения формы не удаляли неудобные строки.

Дополнительная подвыборка с минимум 10 заполненными признаками описательная: она меняет состав случаев и не является новым независимым тестом. Точные совпадения и дубликаты подсчитаны, но отсутствие стабильных идентификаторов не позволяет доказать независимость пациентов. Клиническая применимость и перенос на население Казахстана не установлены.

## Воспроизведение

Из корня `deployment/cardio-site` или рабочего checkout, с установленными Node и Python:

```text
python scripts/build-evaluation.py --archive PATH_TO_ORIGINAL_ZIP
python scripts/build-evaluation.py --archive PATH_TO_ORIGINAL_ZIP --check
node scripts/evaluate-transfer.mjs --archive PATH_TO_ORIGINAL_ZIP
python -m unittest discover -s tests -p test_evaluation.py
npm run build
npm test
python -m unittest discover -s python/tests
```

Для последней команды нужны FastAPI/httpx из исходных `requirements-tested.txt`. Новые маршруты проверяются отдельно от обучения и загрузки joblib. Генераторы читают CSV из исходного архива без публикации строк. SHA-256 архива, исходных CSV, отчётов и модели доступны в JSON. `build-evaluation.py --check` сравнивает воспроизводимый результат без замены даты сохранённого отчёта.

Локальная Python-версия получает `cardio/evaluation.py`, регистрацию маршрутов до общего API fallback и два новых файла в `reports/` при упаковке `scripts/package-diploma.py`. Исходные модели, отчёты и черновики документов сохраняются побайтно. Полный старый Python/ML-набор тестов этим обновлением не перезапускался.

Определения: [scikit-learn — метрики](https://scikit-learn.org/stable/modules/model_evaluation.html), [калибровка](https://scikit-learn.org/stable/modules/calibration.html), [UCI Heart Disease](https://archive.ics.uci.edu/dataset/45/heart%2Bdisease).
